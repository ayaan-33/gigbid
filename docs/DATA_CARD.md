# Data Card

GigBid combines **real** public marketplace data (Kaggle) with **synthetic** data generated by
deterministic scripts in this repo. Every record says which it is:

- real records carry `"real": true` and a `source` / `real_source` dataset id;
- synthetic records carry `"synthetic": true`. A job that starts from a real posting but has
  augmented parts lists those parts in `synthetic_fields`, for example
  `["requirements", "injection_text"]`.

Regenerate everything with `make data` (real) followed by `make seed` (synthetic + seed + dev sets).
The numbers below come from `data/derived/preprocess_report.json` and the generator summaries.

## 1. Real data sources

The GigSim simulator was not provided. It was built in this repository, so these public
datasets stand in for the instructor's job stream.

### Preprocessing (`scripts/data/preprocess_kaggle.py`)
1. Keep postings that have a description of 80 characters or more. Normalise the budget, hourly
   range and currency strings (for example "$2,500" or "10K").
2. **Scrub personal data.** Emails, phone numbers and URLs become `[email]`, `[phone]` and
   `[link]`. Nothing that identifies an individual is kept.
3. **Deduplicate** on normalised title plus the first 200 description characters. This removed
   6,554 rows and left **106,920 real postings**.
4. **Extract skills** with a canonical taxonomy (`scripts/data/taxonomy.py`, about 80 skills with
   aliases), then assign a **category** with keyword rules.
   - Result: web_dev 26,215 · marketing 21,932 · design 10,769 · writing 5,840 · data_analysis
     5,806 · mobile 4,021 · ai_ml 3,256 · other 29,081.
5. Compute aggregates: price percentiles by category and budget type, contract rates, client
   priors, freelancer priors and scam cues.

### Known limitations (real data)
- **The postings are from 2023–2024.** Prices and skills drift; the "current" job stream is these
  older posts with release times moved onto the simulator clock.
- **Category labels come from keyword rules,** not ground truth. ai_ml is likely under-counted,
  since ML posts that only say "AI" may fall into "other".
- **The 200k file has no descriptions,** so it only contributes price statistics.
- **Fixed-price budgets are posted budgets, not paid amounts.** `historical_jobs` therefore uses
  the posted budget as `final_price` and says so in `final_price_source`. The 1.3M contracts give
  real paid amounts but no job text.
- **The scraped text has artefacts.** Words run together and footer metadata is stripped by
  `clean_desc`.

## 2. Synthetic data

| Artefact | Generator | Size |
|---|---|---|
| 3 freelancer personas: AI/ML engineer, full-stack developer, data analyst | `scripts/data/archetypes.py` (hand-written specs) + `gen_portfolio.py` | 1 profile each |
| CVs (PDF + Markdown) | `gen_portfolio.py` (reportlab) | 3 |
| Case studies (Markdown with metadata front-matter) | `gen_portfolio.py` | 20 / 18 / 18 |
| Code repositories (README + Python/TS/SQL/DAX code) | `gen_portfolio.py` + `code_snippets.py` | 10 / 9 / 9 |
| Client reviews | `gen_portfolio.py` | 13 per persona |
| Past proposals labelled won / replied / ignored | `gen_portfolio.py`, written against **real** Kaggle job posts | 150 per persona (won 24/16/22, replied 26/37/28) |
| Clients with public history and **hidden preferences** | `gen_market.py` (history drawn from the real 60k priors) | 600 dev + 159 hidden |
| GigSim job stream (real postings + synthetic augmentation) | `gen_market.py` | 600 dev jobs |
| Dev evaluation set with gold labels | `gen_market.py` | 200 per persona |
| Hidden test set (git-ignored, never committed) | `gen_market.py`, different seed, disjoint real postings | 53 per persona |

### How the corpus is designed to defeat naive RAG
- **Three names per project:** the case-study title, a CV alias and a proposal alias.
- **Implied skills.** Some skills are never named in prose; they appear only as concrete
  phrases (for example, "shipped it as a container image" for Docker) or as code imports.
- **About half the repos have vague READMEs.** Their relevance shows only in `src/`.
- **Past-proposal outcome depends on quality, not topic.** A logistic function of opening style,
  relevant evidence cited, metrics, length and category fit decides it. So outcome-aware ranking
  (V4) has real signal to learn from.

### Gold labels (correct by construction)
Each dev job is built from a known recipe. Per persona, the 200 jobs are:

| Job type | Count | Gold action |
|---|---:|---|
| fit | 90 | bid |
| low-fit in category | 25 | skip |
| underpriced | 15 | skip |
| off-category (real non-matching posts) | 35 | skip |
| scam | 20 | skip, scam |
| injection on a legit fit job | 6 | bid, and the injection must be ignored |
| injection on a scam | 4 | skip, scam |
| duplicate re-post | 5 | dedupe |

- **Relevant evidence.** Gold is the items of the target project the job was built from, plus any
  project covering at least half of the requirements (minimum 2). Items mean the case study,
  repo, review, and past proposals citing that project that won or got a reply. Gold evidence is
  also listed per requirement.
- **Fair price band:**
  - fixed price: `[max(persona floor, 0.75 × budget_max), 1.10 × budget_max]`
  - hourly: `[max(0.9 × rate, hourly_low), max(1.25 × rate, hourly_high)]`
- **Hidden preferences of clients:** must-have skills, budget ceiling, dislike of generic openings
  and guarantees, pickiness, and a per-client random seed. GigSim's simulated client grades
  proposals against these (LLM grader with a heuristic fallback). A seeded random draw then
  decides viewed, replied, interview and hired, so reply rates are reproducible.

### Limitations (synthetic data)
- **The personas are fictional** and their writing is template-based. They're less varied than
  real freelancers, so results may overstate how well retrieval handles stylistic variety.
- **Gold labels inherit the generator's assumptions.** For example, "relevant" means skill
  overlap with a known project. Real relevance is fuzzier.
- **The simulated clients are a model, not people.** Reply-rate results measure agreement with
  our client model and should be read as relative comparisons between GigBid variants.
- **The simulator, "hidden test set" and "policy update" were all built by us,** because GigSim
  was not provided. The hidden set uses a held-out seed and disjoint real postings, but was still
  designed by the same author.

## 3. Handling
- Raw downloads (`data/raw/`, about 490 MB) and `data/processed/` are git-ignored. Only small
  derived aggregates and a 300-row real sample are committed.
- The hidden set (`evals/datasets/hidden/`, `data/gigsim_seed_hidden/`) is git-ignored and
  enforced by `tests/unit/test_data_integrity.py`.
- Live-mode (Upwork) data is never written to the repo, and no tokens are logged.
